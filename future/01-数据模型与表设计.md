# 数据模型与表设计

> 服务端：`server/src/db/models.ts`（Sequelize 模型）、`db/mysql-store.ts`（方法）、`db/store.ts`（接口）、`handlers/*.ts`（事件）。
> 约束：所有业务表带 `companyId`，非本公司数据不显示。时间统一存 DATE(3)，返回 ISO 字符串。

## 1. 新增表一览

| 表名 | 中文 | 用途 |
|------|------|------|
| requirements | 需求 | TAPD 需求模块 |
| bugs | 缺陷 | TAPD 缺陷模块 |
| plans | 计划 | 版本 / 里程碑计划 |
| documents | 文档 | 项目文档 |
| wiki_pages | Wiki | 知识库页面 |
| requirement_links | 需求-任务关联 | 需求勾选关联任务 |

## 2. 各表字段（DDL 语义，Sequelize 定义为准）

### requirements 需求
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK auto | 主键 |
| company_id | BIGINT | 公司 |
| project_id | BIGINT nullable | 所属项目 |
| code | STRING(32) | 需求编号（如 REQ-100001） |
| title | STRING(128) | 标题 |
| description | TEXT | 描述 |
| category | STRING(32) | 分类：未分类 / 产品需求 / 技术需求 |
| priority | STRING(32) | 优先级：Nice To Have / Middle / High |
| status | STRING(32) | 待规划 / 进行中 / 完成 / 已关闭 |
| handler_id | BIGINT nullable | 处理人 |
| creator_id | BIGINT | 创建人 |
| start_time | DATE(3) | 预计开始 |
| due_time | DATE(3) | 预计结束 |
| completed_time | DATE(3) nullable | 完成时间 |
| created_at / updated_at | | 时间戳 |

## 3. 状态枚举（常量，沿用现有风格）

```ts
// 需求
const REQ_STATUS = ['planning', 'in_progress', 'done', 'closed']       // 待规划/进行中/完成/已关闭
const REQ_PRIORITY = ['nth', 'middle', 'high']                          // Nice To Have/Middle/High
const REQ_CATEGORY = ['uncategorized', 'product', 'tech']

// 缺陷
const BUG_STATUS = ['pending', 'processing', 'verified', 'closed']     // 待处理/处理中/已验证/已关闭
const BUG_SEVERITY = ['minor', 'normal', 'major', 'critical']          // 轻微/一般/严重/致命
const BUG_PRIORITY = ['low', 'middle', 'high']

// 计划
const PLAN_STATUS = ['not_started', 'in_progress', 'done', 'canceled']
```

## 4. 聚合（仪表盘 / 成员跟踪，不建表）

在 store 提供聚合查询：
- `dashboardStats(companyId, projectId?)` → { newRequirement30d, overdueRequirement, bugResolveRate, unresolvedBug, requirementByStatus, bugBySeverity, requirementTrend, bugTrend }
- `memberTracking(companyId, projectId?)` → 每位成员 完成/进行中/超时 任务数
