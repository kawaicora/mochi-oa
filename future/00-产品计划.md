# mochi-oa 项目管理 · 产品计划

> 产品经理：豆包 · 文档日期：2026-09-27 · 分支：feature/task
> 目标：把现有「任务流程系统」扩展为 TAPD 式完整项目管理（需求 / 缺陷 / 计划 / 文档 / Wiki / 仪表盘 / 成员任务跟踪 / 甘特图），在客户端 `src/renderer/src/components/` 下实现，服务端补数据模型与 API。

## 一、范围与模块

参考 TAPD 界面（`docs/ref_*.png` 截图），本次新增 / 完善以下模块：

| # | 模块 | 视图 | 数据表 | 说明 |
|---|------|------|--------|------|
| 1 | 任务（已有） | 列表 / 看板 / 甘特图 | projects, project_members, tasks, task_assignments, task_comments, task_issues, task_extensions, task_status_logs | 保留现有能力 |

## 二、里程碑

1. **M1 文档**：本目录（00~04 文档）——产品计划、数据模型、API、界面方案。
2. **M2 服务端**：新增 5 张表（requirements/bugs/plans/documents/wiki_pages）+ store 方法 + task 之外的模块 handler + index 注册；`docker compose up -d --build` 建表。
3. **M3 客户端数据层**：`stores/app.ts` 增加各模块 fetch/create/update/delete 方法 + IPC 桥（`shared/ipc.ts`、`preload/index.ts`、`main/server-ipc.ts`、`main/net/server-client.ts`）。
4. **M4 客户端 UI**：TaskView 顶部加 TAPD 式模块导航（需求/缺陷/计划/文档/Wiki/仪表盘/成员跟踪），各模块独立视图组件。
5. **M5 验证**：双端 typecheck、服务端重建、脚本截屏核对。

## 三、约束与原则

- **权限**：模块数据均关联 `companyId`，非本公司不显示（沿用任务系统规则）。
- **公司角色**：owner / admin 可管理（增删改 + 流转），member 可查看 / 参与执行。
- **状态流转**：需求、缺陷、计划沿用「状态按顺序流转 + 必填说明」的既有约定。
- **关联**：需求可勾选关联任务（任务仍独立）；缺陷可关联需求。
- **界面**：TAPD 浅色办公风，顶部模块导航 + 左侧项目侧边栏 + 主区多视图 + 右侧详情。
- **不动别的功能**：消息、会议、日历、闹钟、通讯录等一律不触碰。
