# Mochi-OA 客户端 · 状态同步审计

> 审计对象：客户端（`src/renderer`）的**状态更新**与**跨部件/跨端同步**链路。
> 数据来源：逐文件核实 `stores/{server,app,rtc}.ts`、`shared/ipc.ts`、`main/net/server-client.ts`、`main/server-ipc.ts`、`components/*.vue` 的订阅代码。
> 结论概览：**任务(Task)模块同步链路完整；TAPD 新模块（需求/缺陷/计划/文档/Wiki）同步链路三层全缺；会话未读的跨端清除缺事件消费。**

---

## 1. 状态分层与「唯一事实来源」

| 层 | 事实来源（store） | 关键 state | 更新入口 |
|---|---|---|---|
| 连接/会话 | `server.ts` | `state{connected,userId,username,activeCompanyId}`、`settings{token,...}` | `init()` + `onServerState` 事件 |
| 组织/会话/未读/在线 | `app.ts` | `companies/departments/members/groups/friends/conversations/messages/onlineMap/selected/unreadTotal/localCache` | `bootstrap()` + 事件回调 + `refresh*()` |
| RTC 通话 | `rtc.ts` | `activeCall{room,peers,remoteStreams,isMuted,...}/incomingDm/incomingGroup/isRecording` | `wire()` 订阅 rtc:* 事件 |

- `server.state` 与 `app.*` 的**部分数据同源重复**：`server.state.activeCompanyId` 是服务端会话态，`app.activeCompanyId` 是本地响应式副本（`switchCompany` 时同步写两边）。
- 组件**不直接持有业务状态**，均经 store 读取；`window.pantry.serverXxx` 是请求通道（发起操作），`window.pantry.onXxx` 是推送通道（别人/他端改了数据）。

## 2. 事件同步链路（socket → main → renderer）

服务端 `io.emit` → `main/net/server-client.ts` `socket.on` → `this.emit` → `main/server-ipc.ts` `sendToMainWindow(IpcEvents.*)` → 渲染层 `window.pantry.on*` → store/组件。

### 2.1 服务端 → main 已转发的事件（server-client.ts）

| socket 事件 | 转出 | 是否达 renderer |
|---|---|---|
| `state` | `state` | ✅ → `onServerState` → `server.state` |
| `chat:message` / `dm:message` | `message` | ✅ → `onServerMessage` → `app.messages/conversations` |
| `presence:update` | `presence` | ✅ → `onServerPresence` → `onlineMap` |
| `user:profileUpdated` | `userProfileUpdated` | ✅ → `onUserProfileUpdated` |
| `message:deleted` | `messageDeleted` | ✅ → `onServerMessageDeleted`（仅当前会话） |
| `conversations:updated` | `conversationsUpdated` | ⚠️ 已转发到 renderer，但 **渲染层无订阅** |
| `sessionNewDevice` / `sessionRevoked` | 同名 | ✅ App.vue |
| `rtc:dmIncoming/Rejected/PeerJoined/PeerLeft/Signal/Ended/GroupCall/ChatMessage` | 同名 | ✅ `rtc.wire()` + `RtcCallRoom` |
| `group:members-updated/invite/dissolved` | 同名 | ✅ app.ts |
| `company:dissolved/updated/removed/added` | 同名 | ✅ app.ts |
| `group:added/removed` | 同名 | ✅ app.ts |
| `friends:updated` | `friendsUpdated` | ✅ app.ts |
| `holiday:updated` | `holidaysUpdated` | ✅ CalendarSide/CalendarView |
| `task:tasksUpdated` / `task:projectsUpdated` | `tasksUpdated` / `projectsUpdated` | ✅ TaskSide/TaskView |
| **`req:/bug:/plan:/doc:/wiki:` 更新** | **— 服务端 handler 未 emit** | ❌ **全缺** |

> 说明：TAPD 的 `requirementsUpdated/bugsUpdated/plansUpdated/docsUpdated/wikiUpdated` 只在 `shared/ipc.ts` 定义了常量名，但：
> 1. 服务端 `project-mgmt.ts` 增删改后仅 `ack` 给发起方，**未 `io.emit` 广播**；
> 2. `server-client.ts` **没有对应 `socket.on`**；
> 3. renderer 的 ReqView/BugView/PlanView/DocView/WikiView **没有 `onXxx` 订阅**。
> 三层全部缺失 → **TAPD 数据没有任何跨端/跨部件同步**。

## 5. 缺口清单与建议

### T1（严重）：TAPD 模块无任何同步
需求/缺陷/计划/文档/Wiki 的增删改、状态流转只在**发起方本端、当次操作后**刷新；其他端（甚至同端其他视图）完全不感知。

- 现象：A 端新建需求，B 端已打开的需求视图不出现；B 端改动缺陷，A 端不更新；文档被他人改名，已打开端停留在旧标题。
- 修法（三层补全）：
  1. **服务端** `project-mgmt.ts`：每个写操作（create/update/status/delete，及 `req:linkTasks`）末尾按公司广播，如 `io.to(companyRoom(companyId)).emit('req:updated', { companyId })`；bug/plan/doc/wiki 同理。
  2. **main** `server-client.ts`：加 `socket.on('req:updated'|'bug:updated'|'plan:updated'|'doc:updated'|'wiki:updated', d => this.emit(...))`。
  3. **renderer** 各视图组件：`onMounted` 订阅 `onRequirementsUpdated(() => load())` 等，`onUnmounted` 取消。

### G1（中）：会话已读跨端不同步
`markRead` 本地把 `unread=0`、通知服务端；服务端广播 `conversations:updated` → main 已转发，但 renderer **没有订阅该事件**，所以他端的红点/未读不会实时减（他端需手动刷新才一致）。

- 修法：App.vue（或 store）订阅 `onServerConversationsUpdated(() => refreshConversations())`；注意与本地 `onServerMessage` 的未读自增逻辑避免互相覆盖（订阅侧只对未选中会话做全量刷新，或按事件携带的会话增量更新）。

### T2（低）：`refreshMembers` 用快照覆盖 `onlineMap`
`refreshMembers()` 里 `for (const m of ms) onlineMap.value[m.userId] = !!m.online` 会用拉取快照覆盖实时 presence 结果，且 `refreshMembers` 常在 `onCompanyUpdated/onUserProfileUpdated` 触发。若快照过期可能导致在线状态短暂回退。建议：快照只更新成员名单，在线值仅由 `onServerPresence` 维护。

### G2（观察）：S4 删除消息仅处理已打开会话
`onServerMessageDeleted` 只过滤 `selected` 会话内的消息；未打开会话的删除不落本地（下次拉历史才生效）。可接受，若需更实时可对 `messages` 全量过滤。

## 6. 统计汇总

- 需状态更新的**组件**：约 20 个（上表 3 节）。
- 需同步的数据**项**：14 项（上表 4 节）。
- 已完整同步：S1,S2,S3,S6,S7,S8,S9,S11,S12,S13,S14（11 项）。
- **部分/缺失：S4(局部)、S5(跨端未读)、S10(TAPD，全缺)**。
- 组件层缺口集中在：`ReqView/BugView/PlanView/DocView/WikiView/DashView/MemberTrackView`（TAPD）与 `ConversationList/App`（会话未读跨端）。
